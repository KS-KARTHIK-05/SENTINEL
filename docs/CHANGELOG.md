## v2: rebuild (October 2026)

An audit of v1 found that its code did not implement what its paper described: there was no PSO, the
fitness function was never called, telemetry stayed at (0, 0), the ledger stored camera-frame offsets
and the swarm size was fixed. v2 is a rebuild, and no v1 number is reused.

- `sentinel_core`: one ROS-independent library holding the channel model, communication graph and local
  minimum spanning tree, link-preserving projection, world-frame ledger with gossip replication,
  constriction PSO, flanking second views, detector model, failure models, metrics and baselines B0–B6.
- `sentinel_sim`: fast simulator, batch runner, equal-budget Optuna tuning of every method, MAPPO
  training and statistics (bootstrap confidence intervals, paired Wilcoxon tests with Holm correction).
- ROS 2 nodes, procedural Gazebo worlds and PX4 software-in-the-loop launch, running the same library.
- YOLO26n and YOLOv8n trained on HIT-UAV with the same protocol.

Design amendments recorded during the rebuild (code comments refer to them):

- **A1 (10 Oct):** information-triggered delivery. A UAV searches freely and delivers a confirmed,
  undelivered victim report once it is older than the hold time `T_hold`.
- **A2 (14 Oct):** the connectivity layer (outage spring, preserved links, projection) is reported as
  a safety property during delivery, not as a source of reporting gains.
- **A3 (14 Oct):** corroborative multi-view fusion replaces naive-Bayes fusion as the default, and the
  fusion rule is set per run. SENTINEL was re-tuned and its rows re-run.
- **A4 (15 Oct):** SENTINEL's tuning space was corrected to the defined design (no soft tether while
  exploring), and SENTINEL was re-tuned. The earlier tuning is kept in `configs/` for the record.

## ICIUS 2026 revision experiments (28–29 October 2026)

- Two baselines added and tuned with the same budget: B7, a hard distance wall to the nearest
  neighbour, and B8, a relay chain from the responder.
- Sensitivity of the spring parameters (λ₀, β, ε, and a distance spring).
- Detector at the operating altitude on Gazebo-rendered thermal frames: the HIT-UAV model and the
  same model fine-tuned on frames from separate worlds.
- An in-loop detector model fitted to the fine-tuned detector's outputs, and a robustness re-run of the
  urban failure settings with it.
- PX4/Gazebo: the earlier three-world check re-run on the current code, and a ten-world check with the
  fine-tuned YOLO26n in the loop.

## Corrections before submission (29–30 October 2026)

- **False-alarm conversion.** Converting the fitted false-alarm rate into the simulator's
  `fp_rate` applied the confidence floor twice, counted only visible debris, and reused one world
  size's value for another. The conversion was fixed and tested, and the fit check, the robustness
  re-run and the fast-simulator side of the ten-world check were re-run.
- **Baseline re-tune and re-run.** Re-running stored missions on the released code showed that the rows
  of six baselines (B0–B4, B6) computed before A3 combined views merged from other UAVs with the earlier
  naive-Bayes rule, while every other row used the corroborative rule. These six baselines were
  re-tuned with the same budget, objective and tuning seeds, and every affected row was re-run on the
  released code, together with the no-projection ablation, whose behaviour had changed. The PX4 checks
  keep B0's earlier tuned values on both the PX4 and the fast-simulator side.
- In both cases the superseded results are archived outside the repository and listed as superseded in
  the extended results.
